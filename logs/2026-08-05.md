## Go2 Gazebo 시뮬레이션 실습

## 오늘 배운 것

1. ROS2에서 로봇의 명령, 상태, 센서 데이터가 각각 다른 토픽으로 전달된다는 것을 배웠다.
    - `/cmd_vel`: 로봇에 선속도와 각속도 명령 전달
    - `/odom`: 로봇의 위치, 자세, 속도 상태 전달
    - `/velodyne_points`: LiDAR의 3차원 점군 데이터 전달
2. `geometry_msgs/msg/Twist` 메시지에서 `linear.x`는 전진·후진 속도, `angular.z`는 회전 속도를 의미한다는 것을 확인했다. 두 값을 동시에 입력하면 로봇이 직선이 아닌 곡선 경로로 이동한다. (원경로와 비슷하게 곡선 이동)
3. `/odom`의 `position.x`, `position.y` 값을 비교하면 로봇이 실제로 어느 방향으로 얼마나 이동했는지 확인할 수 있었다.
4. LiDAR 데이터는 `sensor_msgs/msg/PointCloud2` 형식으로 전달되며, RViz에서 `/velodyne_points` 토픽을 추가하면 로봇 주변의 장애물을 점군 형태로 시각화할 수 있었다.
5. `ros2 bag record`를 사용하면 `/odom`과 LiDAR 데이터를 파일로 저장할 수 있고, 이후 `ros2 bag info`를 이용해 녹화 시간과 메시지 개수를 확인할 수 있다.
6. `ros2 topic bw`를 통해 토픽별 네트워크 대역폭을 비교했다. 단순한 속도 명령인 `/cmd_vel`의 데이터 크기가 가장 작았고, 수천 개의 점을 포함하는 LiDAR 데이터의 크기가 가장 컸다.

## 막힌 것 / 이해가 더 필요했던 것

1. Gazebo와 RViz를 실행하던 중 컴퓨터 화면이 한 번 완전히 멈췄다. 재부팅 후 메모리를 확인했지만 RAM 부족은 아니었으며, Gazebo와 그래픽 처리 과정에서 일시적으로 문제가 발생했을 가능성이 있다고 판단했다.
2. Gazebo의 RTF가 약 0.39로 나타나 실제 시간보다 시뮬레이션이 느리게 진행되었다. 이후에는 불필요한 프로그램을 줄이고, 지속적으로 출력되는 명령에는 `timeout`을 사용하여 시스템 부하를 줄였다.
3. `/cmd_vel`을 계속 발행했을 때 터미널에 `publishing #...`이 빠르게 출력되었다.  `-rate 10` 설정에 따라 초당 10번씩 정상적으로 메시지를 발행하는 과정이었다.
4. 사각형 경로는 시간을 기준으로 이동과 회전을 제어했기 때문에 정확한 정사각형이 되지 않을 수 있었다. `/odom` 값을 실시간으로 확인하여 목표 거리와 목표 각도에 도달했을 때 정지하도록 코드를 개선할 수 있을 것 같다.
5. LiDAR의 `PointCloud2` 메시지 내부에서 각 점의 x, y, z 좌표가 실제로 어떤 방식으로 저장되는지는 아직 충분히 이해하지 못했다.

## 한 줄 소감

직접 보낸 `/cmd_vel` 명령이 Go2의 움직임으로 이어지고, 그 결과가 `/odom`과 LiDAR 데이터로 다시 확인되는 과정을 실습하였고, ROS2의 명령,상태,센서 흐름을 이전보다 구체적으로 이해할 수 있었다. Gazebo에서 Go2가 직접 움직이는 모습을 확인하니 흥미롭고 시뮬레이션이 더욱 실감나게 와닿았다.
